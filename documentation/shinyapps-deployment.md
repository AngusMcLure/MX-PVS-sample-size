# shinyapps.io deployment

This repository is configured to deploy the interactive R Markdown document
`group-testing-sample-size.Rmd` to shinyapps.io whenever a commit is pushed
to `main`. Commits pushed to feature branches do not deploy. Pull requests
also do not deploy; the deployment happens after changes are merged into
`main`.

## One-time setup

1. In your shinyapps.io account, create an account token from the account
   dashboard's **Tokens** page. Copy the account name, token, and secret.
2. In the GitHub repository, open **Settings → Secrets and variables → Actions**.
3. Add these repository secrets:
   - `SHINYAPPS_ACCOUNT`: the shinyapps.io account name (not your email).
   - `SHINYAPPS_TOKEN`: the token generated by shinyapps.io.
   - `SHINYAPPS_SECRET`: the matching token secret.
4. Optionally add the repository Actions variable `SHINYAPPS_APP_NAME` to
   choose the app's URL name. If omitted, the workflow uses
   `mx-pvs-sample-size`.

The app URL will be:

`https://<SHINYAPPS_ACCOUNT>.shinyapps.io/<SHINYAPPS_APP_NAME>/`

The app name must be available on shinyapps.io. If it is already taken, set
`SHINYAPPS_APP_NAME` to another available name in the repository Actions
variables.

## Deployment behaviour

- Every push to `main` triggers a deployment, including merge commits from
  pull requests.
- Pushes to any other branch do not trigger deployment.
- Deployment credentials are stored as GitHub Actions secrets and are not
  committed to the repository.

The workflow uses `rsconnect::deployDoc()` because the application is an
R Markdown document with `runtime: shiny`. It deploys the document and its
required supporting files as a shinyapps.io application.
